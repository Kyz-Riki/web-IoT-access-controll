## 1. Ringkasan Eksekutif

Pada tanggal **25 November 2026**, telah diselesaikan perencanaan, implementasi penuh (Database, Backend FastAPI, dan Frontend Dashboard), pengujian end-to-end, serta perbaikan styling UI untuk pembaruan sistem manajemen kartu dan karyawan:

1. **Edit Nama Jadwal Akses (Cascade Rename)** agar nama jadwal yang sudah dibuat dapat diubah dan otomatis menyinkronkan seluruh kartu terkait.
2. **Import Data Karyawan dari Excel (`.xlsx`) & CSV (`.csv`) dengan Editable Preview**, lengkap dengan deteksi kolom otomatis, penanganan *merge cell* dan divisi kosong, serta **auto-matching Divisi ↔ Jadwal Akses**.
3. **Arsitektur Tabel Terpadu Manajemen Kartu & Karyawan** (`uid` nullable) sehingga karyawan hasil import langsung muncul di tabel dengan Nama, Divisi, dan Level Akses terisi penuh, tinggal memasangkan kartu RFID saat tap.
4. **Registrasi Kartu Fleksibel** (Pilih Nama hasil import, Scan langsung dari baris tabel, Ketik Manual, serta *Simpan & Scan Berikutnya*) + fitur **Lepas Kartu** (*unlink*) untuk penggantian kartu hilang/rusak.
5. **Integrasi Kolom Divisi di Seluruh Aplikasi** (Manajemen Kartu, Log Akses, Export CSV, dan Live Feed Dashboard) tanpa memerlukan perubahan atau *flash* ulang firmware ESP32.
6. **Perbaikan Kompatibilitas Warna Tailwind CSS v2.2.19** pada tombol preview, tab filter, dan badge status.

### D. Pembaruan Backend API (FastAPI)

#### 1. Router Kartu & Import Karyawan (`server/routers/cards.py`)
Menambahkan dan memperbarui seluruh endpoint berikut (dengan urutan route statis di atas `/{card_id}`):

| Endpoint | Method | Fungsi Utama |
| :--- | :---: | :--- |
| `/api/cards` | `GET` | Daftar kartu & karyawan terpadu dengan filter `search` (Nama/Divisi/UID), `division` (termasuk `__NONE__`), `access_level`, `is_active`, dan `card_status` (`all` \| `registered` \| `unassigned`). |
| `/api/cards/count` | `GET` | Total baris sesuai filter untuk pagination. |
| `/api/cards/summary` | `GET` | Ringkasan counter untuk tab cepat (`all`, `registered`, `unassigned`). |
| `/api/cards/divisions` | `GET` | Daftar divisi unik untuk dropdown filter dan autocomplete form. |
| `/api/cards/unassigned` | `GET` | Daftar seluruh karyawan yang belum memiliki UID kartu untuk pencarian cepat saat registrasi. |
| `/api/cards/template` | `GET` | Unduh template kosong dalam format **Excel (`.xlsx`)** maupun **CSV (`.csv` + UTF-8 BOM)**. |
| `/api/cards/import/parse` | `POST` | Parse file `.xlsx` / `.csv` (maks. 2 MB / 5.000 baris), auto-deteksi baris header (aman meski ada kop judul perusahaan), auto-unmerge *merge cell* vertikal, auto-deteksi kolom Nama/Divisi/Level, **auto-match Divisi ↔ Jadwal Akses (*case-insensitive*)**, dan penandaan duplikat DB/file untuk Editable Preview. |
| `/api/cards/import/commit` | `POST` | Menyimpan seluruh baris final hasil edit di preview secara atomik ke tabel `cards` dengan `uid = NULL`. |
| `/api/cards/bulk-level` | `PUT` | Mengubah `access_level` seluruh baris pada satu divisi (atau `(Tanpa Divisi)`) dalam satu aksi. |
| `/api/cards` | `POST` | Mendaftarkan kartu baru (mode manual) atau menambahkan 1 karyawan baru tanpa UID terlebih dahulu. |
| `/api/cards/{id}` | `PUT` | Mengedit Nama Karyawan, Divisi, Level Akses, Status Aktif, atau memasangkan `uid` baru (dengan proteksi duplikat UID `409 Conflict`). |
| `/api/cards/{id}/unlink` | `POST` | Melepas `uid` kartu (`uid = NULL`) saat kartu hilang/rusak tanpa menghapus identitas karyawan, sehingga kartu lama langsung mati dan siap dipasang kartu pengganti. |
| `/api/cards/{id}` | `DELETE` | Menghapus permanen data karyawan/kartu. |

#### 2. Integrasi ESP32, Pintu, Log & Dashboard
- **`server/routers/esp.py`**:
  - `get_whitelist()`: menambahkan filter `AND uid IS NOT NULL AND TRIM(uid) != ''` agar karyawan yang belum punya kartu **tidak** dikirim ke memori/NVS ESP32.
  - `handle_register_scan()`: menyertakan `existing_division` pada broadcast WebSocket jika kartu yang di-tap sudah terdaftar.
  - `handle_tap()` (jalur **online** dan **offline** `validated_locally=True`): membaca `division` dari tabel `cards`, menyimpannya ke `access_logs`, dan mem-broadcast `employee_name` serta `division` via WebSocket.
  - `_check_schedule()` dan pengecekan `admin`: diperbaiki menjadi **case-insensitive** (`LOWER(access_level) = LOWER(?)` dan `access_level.lower() != "admin"`) agar selaras dengan `strcasecmp` pada firmware ESP32.
- **`server/routers/doors.py`**:
  - `remote_unlock()`: menyertakan `division = "Remote Web"` pada insert `access_logs` dan broadcast WebSocket agar format log konsisten.
- **`server/routers/logs.py`**:
  - Memperluas pencarian `search` pada `list_logs`, `count_logs`, dan `export_logs_csv` agar mencakup kolom `division`.
  - Mengembalikan `employee_name` dan `division` pada setiap item `AccessLogResponse`.
  - Memperbaiki export CSV menggunakan modul standar `csv.writer` + **UTF-8 BOM (`\ufeff`)** agar rapi saat dibuka di Excel Windows, dengan kolom: `Timestamp`, `UID`, `Nama Karyawan`, `Divisi`, `Access Level`, `Status`, `Alasan Denied`, `Pintu`.
- **`server/main.py`**:
  - Memperbarui `GET /api/dashboard/stats`: `total_cards` dan `active_cards` hanya menghitung kartu ber-UID, menambahkan `unassigned_cards`, serta menyertakan `division` dan `employee_name` pada `recent_logs`.

- **Perbaikan yang Diterapkan**:
  - Menyeragamkan tombol **Simpan & Import** di preview dan seluruh tab filter aktif (**Semua**, **Sudah Ada Kartu**, **Belum Ada Kartu**) menjadi **biru solid** (`bg-blue-600 text-white hover:bg-blue-700`) dengan badge angka `bg-blue-500 text-white`.
  - Mengonversi seluruh kelas warna pada `cards.html`, `logs.html`, dan `index.html` ke palet resmi Tailwind v2 (`green-*`, `yellow-*`, `purple-*`, `red-*`, `blue-*`).
  - Mengganti tinggi scroll arbitrary (`max-h-[38vh]`, `max-h-[78vh]`, `max-h-[82vh]`) menjadi inline style `max-height` standar dan menambahkan aturan `button:disabled { opacity: 0.5; cursor: not-allowed; }` di `<style>`.

## 3. Hasil Pengujian & Verifikasi

1. **Compile Check Python (`py_compile`)**: Seluruh 8 file backend Python lulus tanpa error.
2. **Migrasi Database Lokal**: `server/data/door_access.db` berhasil dimigrasi (`cards.uid` nullable, `cards.division` dan `access_logs.division` terpasang).
3. **15 Skenario Uji End-to-End HTTP (Lulus 15/15)**:
   - Migrasi database dengan preservasi data kartu lama.
   - Autentikasi login Owner JWT.
   - Pembuatan jadwal akses per divisi (`Engineering`, `Produksi`, `HRD`).
   - Unduh template `.xlsx` dan `.csv` (UTF-8 BOM).
   - Parse Excel `.xlsx` dengan kop judul baris 1, kolom ekstra HRD, *merge cell* vertikal pada divisi, divisi kosong, auto-match *case-insensitive*, dan deteksi duplikat file.
   - Parse CSV ber-BOM dengan delimiter titik koma (`;`).
   - Commit hasil Editable Preview (6 karyawan tersimpan dengan `uid = NULL`, termasuk 2 karyawan bernama sama di divisi berbeda).
   - Verifikasi `/api/cards/summary`, `/api/cards/unassigned`, pencarian divisi mengandung `&` (`Finance & Accounting`), dan filter `(Tanpa Divisi)` (`__NONE__`).
   - Verifikasi `/api/esp/whitelist` **tidak** menyertakan karyawan tanpa UID.
   - Pemasangan UID kartu (`PUT /api/cards/{id}`) & penolakan duplikat UID (`409 Conflict`).
   - Pencatatan divisi pada tap online, sync tap offline, `/api/dashboard/stats`, pencarian `/api/logs`, dan hasil export CSV `/api/logs/export`.
   - Fitur *Lepas Kartu* (`/unlink`): kartu lama langsung ditolak (`unregistered`) sementara data karyawan tetap tersimpan.
   - Ubah level akses massal per divisi (`/bulk-level`).
   - Validasi jadwal **case-insensitive** (`nightshift` cocok dengan rule `NightShift` → `out_of_schedule`).
   - Seluruh halaman HTML (`/`, `/cards`, `/logs`, `/schedules`) merespons `200 OK`.

> **Catatan Hardware ESP32**: Firmware ESP32 tidak mengalami perubahan dan tidak perlu di-flash ulang. Untuk menjamin akurasi mode **offline** (fallback NVS ESP32), perhatikan bahwa buffer `char accessLevel[12]` pada `access_control.h` saat ini menampung maksimal **11 karakter** (saat online panjang nama jadwal bebas).
